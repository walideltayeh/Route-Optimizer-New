## Review of the Hillpace v1 spec: corrections and additions

**Verdict:** the spec is strong on compliance framing. Its weakest point is the reliability pillar. The locked-screen cue design as written will fail in three ways: notification sounds won't play, the permission prompt pops up unasked, and the Live Activity freezes. All three are fixable.

### Claims I checked that hold up (no change needed)
- Every pinned version exists on npm today: `@capacitor/core` 8.6.0, `local-notifications` 8.3.1, `text-to-speech` 8.0.2, `keep-awake` 8.0.1, `@capgo/capacitor-live-activities` 1.2.5, `@capgo/capacitor-native-audio` 8.4.38, Flomentum 0.8.3 and `@capacitor/assets` 4.0.0. The four third-party plugins I opened all ship a `Package.swift`, so the Capacitor 8 Swift Package Manager default is fine.
- `@capacitor/local-notifications` 8.3.1 supports `interruptionLevel: 'timeSensitive'` (since 8.1.0).
- The TTS plugin really does set `usesApplicationAudioSession = false` (TextToSpeech.swift:15).
- Guideline 4.3(b) names "simple timers" explicitly. 5.1.2(i) includes the third-party AI consent rule and "may not require users to enable system functionalities (such as push notifications…)", so citing it for "works with permissions denied" is correct. 2.5.19 exists and bans hidden or dormant features.
- The keyword string is exactly 100 bytes. The calorie check (9.5 net kcal/min) and the Hall band example (3.4–6.0 kg) both recompute correctly.

### Technical corrections
- **[MUST] Notification sounds in `www/sounds/` will not play.** In 8.3.1, `resolveSound()` only lists the top level of `public/` (not subfolders) and then falls back to the bundle root. `www/sounds/jog.caf` ends up at `public/sounds/jog.caf` and is never found, so the notification arrives with no sound. Fix: put the `.caf` files in the `www/` root with a prefix (`www/hp_jog.caf`) and pass `sound: 'hp_jog.caf'`, or add them to the App target's Copy Bundle Resources. Confirm on a device.
- **[MUST] `presentationOptions` is a plugin-wide config key, not a per-notification field** (`plugins.LocalNotifications.presentationOptions` in `capacitor.config.json`, since 8.2.0). For each cue notification use `foreground: false` (8.3.0+) or `silent: true`. Those per-notification flags live in an in-memory lookup that is lost after the app relaunches, so also set `"LocalNotifications": {"presentationOptions": []}` in 6.3. Add that block to the config sample.
- **[MUST] `schedule()` and `update()` now ask for notification permission themselves** (8.3.0+). If a user taps "Not now", the system prompt will appear when they press Start (cue scheduling) or save reminders. That breaks the "prompt only when the user taps" promise in 3.1 screen 12. Wrap every schedule/update call in `checkPermissions()` and continue only when it returns `granted`, and add a unit test in `platform.js`.
- **[MUST] Time-sensitive notifications do not override the Silent switch.** Only Critical Alerts do, and they need an entitlement Apple approves; workout cues won't qualify. Locked phone plus Silent means a banner and vibration, not a spoken clip. Rewrite the pre-run sheet, the permission card ("give interval cues if my phone locks") and the review notes ("with a spoken sound") to say voice cues need the screen on, and that a locked phone gets a banner and vibration (plus sound when Silent is off). Note: one consumer article claims the opposite, but developer documentation and Apple's iPhone guide agree with this.
- **[MUST] The P1 Live Activity as specified won't work locked.** `@capgo/capacitor-live-activities` 1.2.5 moves `startTimerSequence()` forward with an in-app `Timer.scheduledTimer` that ticks every second (CapgoLiveActivitiesPlugin+Timer.swift:75). With no background mode the app is suspended at lock, so the activity freezes on the current segment. The plugin contains no `LiveActivityIntent`/`AppIntent`, so there are **no lock-screen Pause/Resume buttons**. Its methods are called from JS. It also plays its own beeps (`countdownBeeps`, `soundEnabled`), which must be turned off. Apple forum answers agree that updating a Live Activity while suspended needs push (and v1 has none) or background runtime. Choose one: (a) cut the scope to "workout in progress, plus elapsed time via `Text(timerInterval:)`, plus the segment at the moment of lock", (b) ship it only together with iOS 26 workout sessions (next item), or (c) move it to v1.1. If buttons are ever added, the intent runs natively, so pause/resume must update the stored run state and cancel/reschedule notifications in Swift, because JS cannot run.
- **[SHOULD] Promote iOS 26 iPhone `HKWorkoutSession` from P2 to a time-boxed v1 spike.** WWDC25 session 322 confirms workout sessions on iPhone, a one-time prompt that keeps workout data available while locked, automatic relaunch with session recovery after a crash, and Siri pause/resume. It suggests a Live Activity for the lock screen. The transcript does **not** say whether the app keeps running or can play audio in the background, so verify on a device. If it does, it is a legitimate base for background TTS and a live Live Activity, which is far better than the notification workaround. Gate it with `#available(iOS 26)` and keep notifications for iOS 17–25. Also note one developer report that `finishWorkout` fails silently while the phone is locked on 26.4+. Keep the retry queue and save only from the unlocked summary screen (unconfirmed report).
- **[SHOULD] Beeps go silent in Silent mode even with the screen on.** The spec routes beeps through native-audio's `focus:true`, which it describes as ambient with ducking, and ambient output is muted by the Silent switch. Use a `.playback` + `.mixWithOthers` + `.duckOthers` session while in the foreground (no background mode needed), or confirm the plugin's category on a device. Treadmill users often have the phone on Silent.
- **[SHOULD] Register the local plugin with `window.Capacitor.registerPlugin('HealthBridge')`** and reach other plugins the same way, rather than through the older `Capacitor.Plugins.X` global. Keep the device smoke-test screen.
- **[SHOULD] HealthBridge details:** set `HKWorkoutConfiguration.locationType = .indoor`. `HKMetadataKeyAverageMETs` must be an `HKQuantity` in kcal/(kg·hr), and elevation must be a length quantity. All samples must fall inside the workout's start and end. Exclude the app's own weight samples with a negated `predicateForObjects(from: HKSource.default())`.
- **[SHOULD] Double counting with Apple Watch:** a user who also starts a Watch workout gets energy and distance twice. Add "I'm also recording on Apple Watch. Save the session without energy and distance." Overlap detection would need read permission for workouts.
- **[SHOULD] Progression caps vs deloads:** coming back from a deload week (−25%) to the next build week is about a +48% jump, which breaks the "≤10–15% per week" rule as written. Measure caps against the last non-deload week.
- **[NIT]** C617.1 (file timestamps in the app container) and CA92.1 (UserDefaults) match Apple's reason codes from memory. I did not re-check them. The Capacitor plugins ship their own manifests, so merge them.
- **[NIT]** The 64-pending limit allows 28 segment changes if you also schedule a T−10 notice for each one. Long HIIT sessions (for example 30/30 × 20, which is 40 changes) need the T−10 notices dropped once the count is over budget.

### App Store rejection risks
- **[MUST] The review notes steer the reviewer to the most timer-like path** (Classics → Steep Steady Walk), which invites a 4.3(b) "simple timer" verdict. Rewrite them as: onboarding → plan reveal → Today → start the plan session → Skip to the end → summary with RPE → adaptation banner → weight trend. Describe every feature specifically (2.3.1(a)). Do not add a hidden demo shortcut (2.5.19).
- **[MUST] Drop the "±15–20% (our estimate)" accuracy figure.** Under 1.4.1, accuracy claims that can't be validated get the app rejected. Say instead that the figures are ACSM-equation estimates that can differ substantially from actual burn and from treadmill or watch readings, and cite the source equations. Remove Tanaka from "How we calculate" until a heart-rate feature uses it.
- **[SHOULD] "Works with Apple Health" in screenshots:** follow Apple's HealthKit marketing and identity rules (official badge only, no Health app icon), or write "Saves to Apple Health" with no icon. This is from general knowledge; I did not check it.
- **[SHOULD] Calorie floor:** max(RMR, 1,200) is too low for men. Use the common clinical floors of 1,200 kcal for women and 1,500 for men and for "prefer not to say" (general guidance, not checked).
- **[SHOULD] Replace the eating-disorder diagnosis question** with an opt-in "Train without calorie and weight numbers" choice, plus a support-resource link under Health & safety. The outcome is the same, there is less sensitive data, and onboarding is less off-putting.
- **[NIT]** Hide the pregnancy question when sex is Male. The Activity-rings reading is stricter than the HIG requires, but it is safe; keep it.

### Missing for a professional v1 in this genre
- **[SHOULD] Make the treadmill-only scope an explicit decision.** The user asked for a full-fledged running and walking app. A cheap middle ground is an "Any surface" mode: the same interval plans cued by effort and talk test instead of speed and incline, for outdoors or a walking pad. GPS route tracking (background location) stays in P2.
- **[SHOULD] A free "Just walk" session in P0:** an open timer that logs speed and incline changes. Every competitor has a quick start.
- **[SHOULD] "Match your console" edit on the summary** (distance and time) before saving to Health, because belts are often off and users nudge speed.
- **[SHOULD] Read daily step count from Health** and show it on Today. Walking-for-weight-loss users expect steps, it supports the NEAT lesson, and it adds native value for 4.2.
- **[SHOULD] Backup reminders on iOS too,** sharing the export to Files. With no account or sync, a lost phone without a device backup means lost history.
- **[NIT]** Default units and first day of the week from the phone's locale. The P1 "Interval Walk 3/3" is the Shinshu University protocol: 3 min fast (about 70% of peak aerobic capacity) and 3 min slow (about 40%), × 5, 4+ days a week (general knowledge, not checked).

### Scope
- **[MUST] Cut v1 scope.** P0 has 29 items, including an unbuilt Swift plugin, a notification engine, an adaptive plan engine, a projection model, migration and import, and a parallel single-file web product with a fallback for every feature, all for a single owner building on a Mac. Treat the web page as a development and test harness only, not a supported product. Move the Live Activity to v1.1. Cut the chart ranges to 1M/3M. Keep the week of TestFlight.

### Safety
- **[SHOULD]** At T0 for big speed jumps, say "start raising to 8.0" rather than "Go, jog". Add an "I feel unwell" action on the pause screen that ends the session and opens the stop-signs sheet.
- **[NIT]** Rename the projection edges. The "lower edge (Hall)" is actually the higher-weight curve.
